# Why it misses
Full normalization optimizes for data integrity and storage efficiency, but it can mean expensive joins on every read — sometimes the wrong trade for the workload.

<Steps>
  <Step icon="db" title="What normalization buys">
    Splitting data to eliminate duplication keeps writes consistent — update one row instead of hunting down every copy.
  </Step>
  <Step icon="net" title="What it costs on reads">
    Reconstructing a full picture of the data often means <flow>joining several normalized tables</flow> together.
  </Step>
  <Step icon="box" title="What denormalization buys">
    Duplicating some data avoids those joins, which matters a lot for <sys>read-heavy, latency-sensitive</sys> paths.
  </Step>
  <Step icon="check" title="The actual rule">
    Normalize by default for correctness, then denormalize deliberately — and only where a specific read pattern demands it.
  </Step>
</Steps>
