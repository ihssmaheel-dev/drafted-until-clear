# Why it misses
The class keyword is syntax on top of prototype chains — objects still inherit by delegating to another live object, not by copying a blueprint.

<Steps>
  <Step icon="net" title="Delegation, not copying">
    When a property isn't found on an object, JavaScript walks up its <Kw>prototype chain</Kw> looking for it — nothing gets duplicated.
  </Step>
  <Step icon="box" title="Objects link to objects">
    Every object has an internal link to another object (its <Flow>prototype</Flow>), forming a chain rather than a fixed class hierarchy.
  </Step>
  <Step icon="gear" title="class is sugar">
    <code>class</code> and <code>extends</code> compile down to the same <Sys>prototype-chain mechanics</Sys> under the hood.
  </Step>
  <Step icon="check" title="Why it matters">
    You can change an object's prototype at runtime — something a truly classical, compile-time inheritance model would never allow.
  </Step>
</Steps>
