# Why it misses
When you click a button inside a `<div>`, the click event doesn't just fire on the button—it travels through every ancestor element in the document tree, enabling efficient event listening patterns.

<Steps>
  <Step icon="layers" title="1. The 3 Event Phases">
    1. **Capturing Phase**: Event trickles down from `window` -> `document` -> `<html>` -> `<body>` down to the target element.
    2. **Target Phase**: Event triggers on the clicked element itself.
    3. **Bubbling Phase**: Event bubbles back up from the target element all the way to `window`.
  </Step>
  <Step icon="shield" title="2. Stopping Propagation">
    - `event.stopPropagation()`: Stops the event from bubbling up further to parent elements.
    - `event.preventDefault()`: Prevents the browser's default action (e.g. following a link `<a>` or submitting a `<form>`).
  </Step>
  <Step icon="zap" title="3. Event Delegation (Performance Win)">
    Instead of attaching 1,000 separate `click` event listeners to 1,000 table rows, attach **one single listener to the parent `<table>`** and check `event.target` when the event bubbles up.
  </Step>
</Steps>

<Tip title="Memory Optimization">
Event delegation prevents memory leaks and eliminates the need to re-bind event listeners whenever new dynamic rows or cards are added to a list.
</Tip>
