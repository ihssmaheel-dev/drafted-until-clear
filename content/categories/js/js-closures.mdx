# Why it misses
Nesting alone doesn't create a closure — what matters is that the inner function keeps access to variables from its outer scope after that scope has finished running.

<Steps>
  <Step icon="box" title="The core mechanic">
    A function remembers the <kw>variables from where it was defined</kw>, not where it gets called.
  </Step>
  <Step icon="key" title="Why it survives">
    Even after the outer function returns, its variables stay alive in memory because the inner function still <flow>references</flow> them.
  </Step>
  <Step icon="gear" title="Where it shows up">
    Private state in module patterns, memoized functions, and callback-based counters all lean on this.
  </Step>
  <Step icon="flag" title="The trade-off">
    Careless closures — especially in loops or long-lived event listeners — are a common source of <bad>memory leaks</bad>.
  </Step>
</Steps>
