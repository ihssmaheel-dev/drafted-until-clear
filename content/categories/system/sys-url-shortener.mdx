# Why it misses
That's a fine starting point, but it skips the parts an interviewer is actually probing: how codes are generated, and how reads scale once traffic grows.

<Steps>
  <Step icon="key" title="Code generation">
    Base62-encode an auto-incrementing ID, or hash the URL and truncate — each has different <Kw>collision</Kw> and predictability trade-offs.
  </Step>
  <Step icon="db" title="Storage shape">
    A simple key-value store (short code → long URL) is enough; a relational DB works too if you need analytics alongside it.
  </Step>
  <Step icon="gear" title="Reads dominate">
    Redirects vastly outnumber creations, so a <Flow>cache</Flow> in front of the datastore matters more than write throughput.
  </Step>
  <Step icon="scale" title="Scaling the redirect path">
    Push the hot path — the actual redirect — behind a <Sys>CDN or edge layer</Sys> so it never has to hit your origin servers at all.
  </Step>
</Steps>
