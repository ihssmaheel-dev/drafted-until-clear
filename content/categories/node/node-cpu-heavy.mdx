# Why it misses
async only helps with I/O-bound waiting — it does nothing to stop synchronous CPU work from occupying the single thread.

<Steps>
  <Step icon="cpu" title="One thread, one thing at a time">
    A tight synchronous loop — image resizing, heavy JSON parsing, hashing — runs to completion before anything else gets a turn.
  </Step>
  <Step icon="users" title="Everyone else waits">
    Every other request queued behind it stalls, even ones that have <Flow>nothing to do</Flow> with the CPU-bound task.
  </Step>
  <Step icon="gear" title="Where the work belongs">
    Offload it to <code>worker_threads</code>, a child process, or an external queue/service so the main thread stays <Good>responsive</Good>.
  </Step>
  <Step icon="check" title="Rule of thumb">
    If a task takes more than a few milliseconds of pure CPU time, it doesn't belong on the <Kw>request-handling thread</Kw>.
  </Step>
</Steps>
