# Why it misses
That's the opposite of Node's model — it describes something closer to a traditional thread-per-request server like older Apache setups.

<Steps>
  <Step icon="loop" title="The one thread">
    Your JavaScript runs on a single thread with an <kw>event loop</kw> managing what runs next.
  </Step>
  <Step icon="gear" title="Handing off I/O">
    For things like network calls or file reads, Node hands the work to the <sys>OS kernel</sys> or, for tasks like DNS lookups and filesystem access, to <code>libuv</code>'s <sys>worker pool</sys>.
  </Step>
  <Step icon="clock" title="Waiting doesn't block">
    While that work happens elsewhere, the main thread is free to keep processing <flow>other requests</flow> instead of sitting idle.
  </Step>
  <Step icon="users" title="The payoff">
    Thousands of connections can be in-flight at once because none of them are holding the single thread hostage while waiting on <flow>I/O</flow>.
  </Step>
</Steps>
