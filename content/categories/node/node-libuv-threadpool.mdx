# Why it misses
Most network I/O — TCP, HTTP — is handled by the OS's async primitives directly, not the thread pool at all.

<Steps>
  <Step icon="box" title="Two async paths">
    Node's async I/O splits into <Sys>OS-level async</Sys> (sockets, most networking) and <code>libuv</code>'s own <Sys>worker pool</Sys> for things the OS can't do async.
  </Step>
  <Step icon="gear" title="What lands in the pool">
    File system calls, DNS lookups via <code>dns.lookup()</code>, and some crypto functions like <code>pbkdf2</code> run on the <Sys>pool</Sys>.
  </Step>
  <Step icon="users" title="The pool is small">
    By default it has only <Flow>4 threads</Flow>, so piling on filesystem-heavy work can create a real bottleneck.
  </Step>
  <Step icon="check" title="Tuning it">
    The pool size is adjustable via the <code>UV_THREADPOOL_SIZE</code> environment variable when that becomes the constraint.
  </Step>
</Steps>
