# Why it misses
Server Components run once on the server, ship zero JS to the browser, and can access server resources directly — they're a fundamentally different execution model.

<Steps>
  <Step icon="cpu" title="Zero client JS">
    Server Components <kw>never ship their code</kw> to the browser. A 50KB component with heavy dependencies adds 0 bytes to the client bundle.
  </Step>
  <Step icon="gear" title="Direct server access">
    They can read files, query databases, and call internal APIs <flow>without an API layer</flow> — no fetch, no loading states, no serialization.
  </Step>
  <Step icon="box" title="The boundary">
    The server renders them to HTML/RSC payload. Client Components pick up where interaction is needed — <code>'use client'</code> marks the boundary.
  </Step>
  <Step icon="check" title="When to use which">
    Default to Server. Add <code>'use client'</code> only for: state, effects, event handlers, browser APIs.
  </Step>
</Steps>
